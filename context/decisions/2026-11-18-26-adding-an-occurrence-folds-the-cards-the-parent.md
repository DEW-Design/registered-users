# 2026-11-18 - Adding an occurrence folds the cards the parent event answers (lab)

- **Nov 18 2026: Adding an occurrence folds the cards the parent event answers (lab).** The designer: "When user tries to add an occurrence, unless methodology defines otherwise, collapse everything except occurrence details for the edit screens. Next to observers, temporal, location it would be good to have text like 'only fill out if you wish to define more precisely than parent event fields'. Build this out on a different page for testing."
  - **Built as a lab, not in the product.** `/proto/occurrence-add` mounts the real `RecordFullView` (`isNew`, the Adelaide Hills seed under its own project id, so the project page is untouched) with two options: A as it is, B folded. The bar emulates what the person adds the occurrence under (a Transect, a Visit, the project), the occurrence type (Individual adds Voucher) and the project's methodology.
  - **The rule** is `occurrenceFolds` in `record-rules.ts`, with the line as `PARENT_DEFINES_HINT`: "Only fill out if you wish to define more precisely than the parent event fields". Under an event, Occurrence details stays open; Temporal details, Observers, Location information carry the line; Voucher and Custom properties fold without one. Under the project nothing folds, because there is no event to take from.
  - **One opt-in prop** on the real view, `foldedInEdit` (section id to the line beside its title). No product caller passes it, so no product screen changed. A folded card opens and closes like a card being read, and keeps what it holds.
  - **A folded card still holds the parent's values.** The new occurrence starts with the parent's start date, observers and coordinates, and saves with them, so what is saved is what the event said. The saved view shows Temporal details, Observers and Location with those values.
  - **Verified in a browser (registered user):** Transect Population: Details open, the other four folded, the three carry the line; opening Temporal and Observers shows 14/10/2025 and Maya Dewitt, Phoenix Baker; save with only a species picked saved an occurrence with those values. Visit Individual: Voucher folds too, no hint on it. Project: nothing folds. Methodology "own location": Location stays open and locked, the others fold. Option A: all open. Enter on a focused folded title opens it. The hint is Barlow 12px, 400, text-tertiary. tsc, eslint and `check:contracts` pass.
  - **Not measured:** touch, the side-panel variant of the add screen, other roles, the Pre-fill sample content switch on this screen, console errors (not read). The hint wraps to two lines beside the 272px left of the card header at 1280px; it sits on one line only where the card is wider.
  - **Open, for the designer (0.4).** (1) Which methodologies ask each occurrence for its own observers, date or location: no source says, so the lab offers three emulated cases and the production table is empty (`own` is empty). (2) Copy or reference: a folded card copies the parent's values at the time of adding, so a later change to the event does not reach the occurrence; the alternative is to store nothing and read the parent at view time. (3) Should a folded card say what it will take ("Same as Transect TR00501")? Not built: new copy not asked for. (4) Whether the project page's Add occurrence (side panel and full screen) takes this once chosen. (5) A failed save does not open a folded card; none of these cards has a required concept the person can empty, except by opening it.
  - **Same day, the designer's follow-up (supersedes the copy, open items 2 and 3 above):** "I can see the inherited details in my edit view but I am unsure if they are entered or inherited ... we will not store these inherited details twice but just pull them from the parent ... the inherited information must be made obvious to the user that the values are inherited, and also allow to override if needed."
  - **Inherited, not copied.** `SurveyRecord.inherits` (optional, additive) names the sections of an occurrence that are its parent event's: Temporal details, Observers, Location information. They are saved empty (`withInherits`) and read from the event whenever the record is shown (`resolveInherited`, applied once, where the edit store builds its list, so every reader gets the event's current values; a record without `inherits` is returned as it is). The source is the nearest event above that has the section (`inheritanceSource`): an occurrence in a Visit takes its location from the Site above, since a Visit has none.
  - **In the edit view** an inherited card says "Inherited from Transect TR00501" in its header (the "Hidden" marker's quiet text), shows the event's values shaded (bg-secondary) rather than as fields, keeps the plain border instead of the editing one, and has one Override with the designer's sentence beside it. Override makes the card the occurrence's own: fields, editing border, and "Use Transect TR00501's values" to go back. What is entered is stored. The same marker shows on a saved occurrence's inherited cards, and Edit on a saved occurrence opens them inherited again.
  - **Verified in a browser (registered user, DOM and computed styles; the preview's screenshot call timed out on every page that session, so nothing was judged by eye):** Transect Population: Temporal, Observers, Location folded with the marker; opened, the body reads the event's values and the card border is rgb(229, 228, 226), the shade rgb(248, 248, 247), 8px radius, the marker 12px 400 text-tertiary; Override gives the editing border (rgb(42, 102, 124)) and "Use Transect TR00501's values"; using it returns to inherited. Overriding Observers, removing one name, picking a species and saving stored `inherits: ["location","temporal"]`, the observers as entered, Temporal and Location rows "Not provided", no stored shape. "Move Transect a day on" moved the occurrence's Start date from 14 to 15 Oct 2025 with it. Edit on the saved occurrence opens Temporal and Location inherited, Observers with the way back. The project page still loads, with no inheritance marker. tsc, eslint and `check:contracts` pass.
  - **Not measured:** the look of the shaded body and the header at any width (no screenshot), touch, the side panel, other roles, the sample-content switch, console errors.
  - **What is not stored twice, and what is.** Date, latitude and longitude stay on the record as the index the tree, map and sort read, and keep the event's value at the time of the last save; the shown record overwrites them from the event. A backend would derive them. The side panel and other readers that do not go through the edit store do not draw the marker yet.
  - **Open, for the designer (0.4).** (1) Granularity: the card is the unit (a whole section is inherited or entered). Overriding only the End date, or only the coordinates, makes the card all entered, starting from the event's values. A field at a time is possible but each of these cards mixes several controls. (2) The saved view marks inherited cards only; entered ones carry no marker. (3) Which methodologies ask for their own details, as before (the table is empty). (4) Should the side panel, the records table and the reports show the marker, and should reports state the source? (5) If the event is deleted or loses the section, an inheriting occurrence shows nothing for it; what should it say?
