# 2026-11-19 - Dataset upload recommends the templates of the methodologies the project accepts, in a table

- **Nov 19 2026: Built in the product (`app/pages/_shared/dataset-upload/dataset-data.ts`, `recommended-templates.tsx` new, `upload-form.tsx`).** The designer: "For dataset upload, the recommended templates section would show actually recommended templates. Also, let's clean up the recommended template cards, and show them as a table instead of cards."
  - **Recommended means this.** A template is recommended for a project when it is the template of a methodology the project accepts (the ones chosen under Systematic in Add Project, `2026-11-19-02`). It was the same three legacy templates (Site Visit Species Load, its Custom variant, Species Data Return) for every project, which belong to no methodology. The mapping (`TEMPLATE_OF_METHODOLOGY`): Bush Assessment Method (BAM) to the Bushland Assessment Method (BAM) template, Rangeland Assessment Method (RAM) to its template, Ramble to Ramble, BCM to Bushland Condition Monitoring (BCM), and Macro Invertebrate BioBlitz to Waterbug Bioblitz - Macroinvertebrates. A methodology with no template (Biological Survey of South Australia, Scattered Trees, Pastoral Assessment, and the rest) recommends none. The templates come from the one list the Template Finder reads.
  - **A table, as the Template Finder draws a template (0.9).** One row each: the template's name and what it is, its Collection method and Species type (the source's own fields, 2.15), and the one Download button. It is the form's embedded table (`EmbeddedTable`, 4.2h: a bordered table with no paging while the rows fit one page); a first version in a `TableCard` failed `check:contracts` 4.2b (a collection table without `bodyScrollable`), and the embedded table is the pattern the contract names for a table in a form. The old `TemplateCard` is gone.
  - **When there is nothing to recommend,** the table is replaced by a compact empty state with "Browse all templates" (to the Template Finder, only where the role can open it): "None of the standard templates is for a methodology this project accepts." when the project has methodologies, and "This project has no methodologies yet, so no template is recommended for it." when it has none (the built-in projects other than Adelaide Hills have no registration here).
  - **Agent calls (each reversible: the one mapping constant, or `recommended-templates.tsx`).** (1) Recommended is read from the methodologies and nothing else: the templates' species type and collection method are all "Flora" and "Others" in the data, so they carry no signal. (2) The Macro Invertebrate BioBlitz and Waterbug Bioblitz pairing is a judgement from the names, for the designer to confirm. (3) The row's line is now "Standard templates for the methodologies this project accepts." (4) The two legacy templates are no longer offered here; they remain in the Template Finder. (5) The Template Finder's cell markup is mirrored in the table's `cell` function, not shared.
  - **Verified (19 Nov 2026, Chromium headless, 1440 by 900).** A project created with BAM, Ramble and Pastoral Assessment: the table has the BAM and Ramble rows, no row for Pastoral Assessment, no horizontal scroll, the Download button whole in its column (the first widths cut it at the right edge). Adelaide Hills (its registration is free text): the empty state with the "has methodologies" line. Zero console errors. `tsc` and `eslint` clean.
  - **Not checked.** The "no methodologies yet" line and the Browse link in a browser (a built-in project with no registration was not opened); the table on a phone; a project with all five template methodologies (five rows).
  - **Open, for the designer.** Whether Analysis/Reporting kinds and Incidental observations should recommend templates too (there is none for them). Whether the legacy templates should be offered when nothing matches. The mapping above.
  - **Touches:** contracts 0.9, 2.15, 4.2, 4.3; `2026-11-19-02`.
