# 2026-11-20 - Explore's Map and table gets occurrence date, collection method and institution rego columns

- **Nov 20 2026: Explore's Map and table reads Project, Class, Scientific name, Species, NSX code, Occurrence date, Collection method and Institution rego # first, with the NSL code hidden; Occurrence Population gets Institution rego #.** The designer's request: three more columns (occurrence date, collection method, institution rego #), NSL hidden, the first eight columns in that order, institution rego # added to Occurrence Population (it was on Occurrence Individual only) and to the data model config, and two more filters: occurrence date, and scientific name as a searchable dropdown.
  - **Columns.** `exploreSpeciesColumns` (`species-detail-report.tsx`) is built from the Species Detail Report's own columns, so a label or a cell changes in one place: the eight named columns first (Project is the pinned one now, the sequence number moves after them), then the rest of the report in its order, `nsl` hidden through `hiddenColumns` (it is in the Columns chooser, which says "1 hidden"). The Species Detail Report itself is unchanged. New: Occurrence date (`dayColumn`, shown as a day, sorted by the ISO day) and Institution rego # (`SpeciesRow.occurrenceDate`, `institutionRego`, read from the record). Collection method is the project's methodology from Add Project (the designer: "Collection methods come from the methodologies in the create a project flow"): `SpeciesRow.methodology`, from `builtInMethodologies` (`accepted-methodologies.ts`), the Survey methodology vocabulary's names ("Bush Assessment Method (BAM)"). The report's own "Collection method and description" column (the observation's seen, heard or captured code) is a different field and stays among the rest, unchanged.
  - **Filters.** `exploreSpeciesAttributes`: the report's five, then Occurrence date (`dayAttribute`: Last 7, 30, 90 days or a custom range) and Scientific name (`optionsAttribute` with `searchable`: a search box at the top of its list, 4.2d).
  - **Population.** `occurrenceSections` gives a Population a Voucher section holding only "Institution rego #"; an Individual keeps its full voucher section. `config/data-model-schema.ts` `Occurrence:Population` lists "Institution Rego #". Explore's own record page (`record-detail.tsx`) draws the same one-field Voucher tab for a Population.
  - **Sample values (0.3).** Adelaide Hills is the one built-in project with a registration, so its methodology (Bush Assessment Method (BAM)) is its own. The other seven built-in projects hold none, so `SAMPLE_METHODOLOGY` gives each one from the BIODATA-117 list (Coorong: Bird survey, 20 minutes, 2 hectare; Flinders: Rangeland Assessment Method (RAM); Kangaroo Island and Naracoorte: Biological Survey of South Australia; Lake Eyre: Bird survey, 500 metre area search; Nullarbor: Rangeland Assessment Method (RAM); Mount Remarkable: Bush Assessment Method (BAM)). They are sample values chosen by project kind, for the designer to confirm. The institution rego is derived from the species group, as the registers in `specimen-records.ts` already are (`REGO_FOR_GROUP`, now exported, one source). The two Adelaide Hills records without a voucher show no rego. The Records report's rego column now fills for Explore-seeded projects too.
  - **Verified live (registered user and BioData Admin):** headings in the order asked, 8 columns first then Species seq #; NSL hidden; the Filter menu lists Occurrence date and Scientific name; typing "Dromaius" in the Scientific name list offers the species and ticking it leaves the 5 Emu rows; Population record page shows a Voucher tab with Institution Rego #; zero console errors. `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` clean. Not checked: a Population's rego on the project page's own Survey records tab (no seeded Population has a rego there), touch emulation of the new filter rows (they are the existing menu).
  - **Open.** "Project" reads "Projects" in the header (the report's label, left as the source has it). A date in July reads "5 July 2026" while the others use three letters: that is the browser's en-AU short month, shared with every date in the app, so it was not changed here.
