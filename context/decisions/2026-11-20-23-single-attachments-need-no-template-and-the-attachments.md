# 2026-11-20 - Single attachments need no template, and the Attachments tab is renamed

- **Nov 20 2026: "Upload attachments" opens on One file, with no template; the project's tab is "Attachments".** The designer: "Can we also cater to single attachment uploads? ... when I upload a single attachment it doesn't let me upload without the excel template file. for single ones, let me just do, make it easy", and "rename 'Artefacts and attachments' to 'Attachments'".
  - **The job and the ground.** Someone has one file for the project (a photo, a PDF) and wants it attached. The project's Upload menu and the header Add menu both open the bulk upload (`bulk-attach-modal.tsx`), which asked for the project's template and a zip, with no way to do just one. A record's own "Add attachment" (`record-quick-actions.tsx`) already did one file: the concept it documents and the file. Principles: say less, make it obvious, reveal in steps; the closest page is that record modal (0.9).
  - **Built (second version; the first had a "One file" and a "Many files" switch, which the designer rejected: "reuse the bulk upload. no need to create two tabs. doesn't make sense").** The one modal, "Upload attachments", takes a single file in the same drop area as the zip and the template. Add one file that is not a zip or a spreadsheet and it shows as a file card, and under it two things are asked: the record (a searchable list of the project's records, "SU00501 Cleland Stringybark Woodland, Site") and the concept of it the file documents; then "Attach file". The template's three steps are hidden once a single file is in, since they are about the other path. A zip or a spreadsheet is the many-files path, exactly as it was (a single spreadsheet goes to the template check; to attach a spreadsheet as a single attachment, use a record's own Add attachment). A file type that is not supported says so. The record and concept controls are shared (`attach-fields.tsx`: `RecordSelect`, `ConceptSelect`, `FileChooser`) with the record's own Add attachment, so there is one version of each (1.7, 1.6). The file's kind and the review of audio and video follow the same rules as before (`kindForFile`, `reviewForNewFile`).
  - **Renamed.** The tab, its table's name and the Add-attachment menu group read "Attachments" (was "Artefacts and attachments"), and §3.13's icon list names it so (`CONTRACTS.md`, then `npm run contracts:rules`; a rename, no clause loosened).
  - **Verified live** (registered user and BioData Admin, Adelaide Hills): Upload > Upload attachments opens with no tabs and the drop area; Attach with nothing added asks for a file; a .txt says it is not supported; one PDF shows its card with Record and Attach to under it; Attach file with no record asks for one; with both chosen the toast reads "one.pdf attached to Site ID" and the Attachments count goes from 7 to 8; a single .xlsx goes to the template check ("No attachments template was found"); header Add > Attachments opens the same modal; a record's Add attachment still works; a new project with no records says so and a press of Attach file gives a toast, not a dead button. Zero console errors. `tsc`, `eslint`, `check:contracts` clean. Not checked: dropping (rather than choosing) a file, the Pre-fill sample content switch with a single file (the sample is the zip), touch, a web link as a single attachment.
  - **Also found.** The dataset upload (Upload dataset) did take a PDF alone: it is Upload attachments that wanted the template. The dataset form's instruction line still reads "Supported file formats for data: .XLS and .XLSX" and may read as a template requirement; left as it is.
  - **Open, for the designer (0.4).** Whether a single file should be able to be a web link too (links are still the record's Add web link and the template). Not committed.
