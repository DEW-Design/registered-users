# 2026-11-19 - Add Project and the dataset upload form keep their answers across a refresh

- **Nov 19 2026: Built in the product (`app/pages/_shared/form-draft-store.ts` new, `registration-flow.tsx`, `form-storage.ts`, `dataset-upload/upload-form.tsx`).** The designer: "Apply zustand persistence for forms, on refresh they should still show."
  - **The store.** `useFormDraft` keeps a form's answers in one zustand store persisted to localStorage (`biodata-form-drafts`), the same plumbing as the other stores (`zustand-persist.ts`: `skipHydration`, rehydrated after the first render so the first paint matches the server's). Each form has its own key and says how it is written and read (`encode`, `decode`): Add Project reuses `serializeForm` and `deserializeForm`, which already carry calendar dates and Sets and leave out the organisation's temporary logo address. A draft is written only after the person changes something (opening a form and leaving it leaves nothing), read once, and a draft that can no longer be read is dropped.
  - **Add Project.** The answers and the sections gone through (so column 2 still ticks them) are kept. The section is already in the address (`?section=`), so a refresh returns to the same step with its answers. The extent picker takes the restored area in (it mirrors its value, `2026-11-18-23`). Cleared by Create project and by Discard in the cancel prompt. The dataset route (`option-2`) has its own key. "Save draft" now says "Your answers are kept in this browser until you create the project." (it said nothing was persisted, which was true until now). Leaving a restored draft asks before discarding, as an edited form does.
  - **Dataset upload form.** The answers (licence, First Nations, IIA reference, permit number, URI / DOI, the privacy tick), the section and the sections gone through are kept per project (`upload-dataset:<project id>`); cleared on Confirm and upload and on Discard. **Files are not kept**: a File cannot be stored, so after a refresh the files are added again (the queue is empty and the form says nothing about it).
  - **Agent calls (reversible: the hook call in each form).** (1) The unticked-visited and "attempted" (the red error marks) state is not kept for Add Project's errors: only what was visited. (2) The Add Project dataset step's own answers (`with-dataset/dataset-step.tsx`, state above the flow) are not kept yet. (3) A form is keyed per browser, not per signed-in user (this edition has one user). (4) No expiry on a draft.
  - **Verified (19 Nov 2026, Chromium headless).** Add Project: typed a name and abstract, a draft appears in storage (none before typing), went on to Data owner, filled a person, refreshed: same section, same values, Individual still selected; back on the first section the name, abstract and start date are there and the earlier steps are ticked; Discard clears the draft and a reopened form is empty. A drawn and used extent survives a refresh; two chosen methods with a methodology survive a refresh; Create project clears the draft and a fresh form is empty. Dataset upload: permit number, URI / DOI, licence and First Nations answer survive a refresh on the second section; the PDF does not; Discard clears the draft. Zero console errors and no hydration message. `tsc`, `eslint --max-warnings=0` on `app/pages` (one warning in `biodata-home/page.tsx`, not from this work) and `check:contracts` clean.
  - **Not checked.** A draft saved by an older build opened by this one (the shapes are new, nothing older exists); a corrupt draft; two tabs at once; storage that is full or turned off; Add Project through the option-2 dataset route; a phone.
  - **Open, for the designer.** The other forms (about a dozen) are not covered: DLA and DSA requests, nominations, notifications, controlled vocabulary, taxonomy, user management, the project page's edit cards and the record form.
