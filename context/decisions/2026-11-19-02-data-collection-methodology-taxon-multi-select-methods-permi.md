# 2026-11-19 - Data collection methodology: taxon, multi-select methods, permits and DOI move to the dataset upload

- **Nov 19 2026: Built in the product. Add Project's "Method and details" is now "Data collection methodology"; the dataset upload says what the project accepts and asks for the permit number and URI / DOI.** The designer, on a screenshot of the step: remove Focus areas; Targeted species becomes Targeted taxon, a combo box above Methodology and not behind an accordion; "nothing else changes on that"; the DOI and permit bits leave the form and "the two text fields" sit under the dataset upload component; the methodologies chosen show on the dataset upload as a heads up; and methodology is a multi-select (checkboxes, not radio buttons), "more than one methodology per project". Then, on the result: the line under the URI / DOI field is a tooltip; a tooltip's black box hugs its text when it wraps; the methodology list is indented; the second and later methodologies are added with "+ Add another methodology".
  - **The step (`option-2/form-sections.tsx`, `sections.ts`).** Titled "Data collection methodology" (its line: "How the data was collected, and which taxa it targets."). Rows: **Targeted taxon** (the same `MultiSelect` as before, same placeholder, now a row of its own: "Only add this if it applies to this project.") then **Methodology** (required; the line is the designer's: "Select any methodologies that are relevant to your current dataset or expected for future loads in this project."). Focus areas, and the Optional details accordion (Targeted species, Permits, URI / DOI number) are gone from the step. A focus area is no longer asked or required; the data field stays (new projects hold "Biological", as before), and the project page still shows and edits it.
  - **The data (`types.ts`).** `collectionMethod` is now `collectionMethods: CollectionMethod[]`. A saved draft or created project with the old field is read into the new one when it is loaded (`form-storage.ts`; checked in the browser with a project edited to the old shape). Every reader was changed: `methodologySummary` (the names and notes of every chosen method, so `methodDetails` and `limitationsAndBiases` carry them all), the review step ("Systematic: ..., Bush Assessment Method (BAM); Incidental observations"), the project page's Collection method row (joined labels), the audit log's diff, the Project detail report, the sample content, the project edit's sample, and the Adelaide Hills seed. New helpers: `collectionMethodLabels` (`data.ts`) and `acceptedMethodologies` (`sections.ts`).
  - **Methodology is checkboxes.** Incidental observations, Systematic, Analysis/Reporting, Other (and Unknown only when a project holds it), each with its hint. Systematic and Analysis/Reporting each carry their own list under them; Other asks what it is. Required: at least one method, and each chosen one needs what it asks for (a systematic methodology, a type of analysis or reporting, a description). The list is indented 80px from the checkbox (the designer drew the line: 56px past the label). The list has room above it (4px more) and below it (16px more), so it reads as a group and does not run into the next choice (the designer, after seeing it: "not enough space between the indent field and the content below"); measured, 48px from "Add another methodology" to the next checkbox. The first is added with the search box; after that the box is out of the way behind **+ Add another methodology** (or "type of analysis or reporting"), which opens it; Escape or a pick puts the button back. The project page's methodology edit is the same component, so it changed too.
  - **Dataset upload (`dataset-upload/*`).** Under "Dataset files" and its queue, **Permit number** and **URI / DOI number** (both optional). Their line ("Enter an existing identifier if known; otherwise, a unique ID will be generated.") is a tooltip on the URI / DOI field's help icon (the input's own `tooltip`). They are stored on the dataset (`permitNumber`, `uriDoi`) and shown on its page; the same two fields are in the Add Project "Upload datasets" step (`with-dataset/dataset-step.tsx`, a shared `DatasetIdentifiers`) and its review rows. At the top of Upload files a grey alert, "Methodologies this project accepts", lists each method with what was chosen under it ("Incidental observations; Systematic: A, B, C. Upload data collected with these."); for a project made in this browser it reads its registration, for Adelaide Hills the sample registration, and for the other built-in projects nothing is said (there is no registration to read). Nothing is added to the alert when a project has no methods.
  - **Tooltip box hugs its text (`components/base/tooltip/tooltip.tsx`), for every tooltip.** The box is as wide as its limit (20rem) when its text wraps, though the balanced lines are shorter, so it was wider at the right than at the left. A layout effect measures the widest line the text sets and narrows the content to it (in the box's own units, so the opening animation's scale does not change the answer). The designer said it applies to every hint box, so it is on for all 23 users of the component, an override of 1.6's "opt-in" for the same reason the hit area is (a change to every tooltip, by the designer's instruction). Measured: the URI / DOI tip 236px wide, its longest line 211.9px, 12px of padding each side, 0.1px spare at the right (it was 320px); the one-line "Home" tip unchanged (54.7px, 0 spare).
  - **Also in `components/base/select/multi-select.tsx`: `defaultOpen` and `onOpenChange`** (additive, defaults leave every caller as it was), so a picker that appears because it was asked for can be open.
  - **Agent calls (each reversible in the file named).** (1) "Data collection methodology" in sentence case, not the designer's title case (2.3).
