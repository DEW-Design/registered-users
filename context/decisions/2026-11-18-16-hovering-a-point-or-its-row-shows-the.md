# 2026-11-18 - Hovering a point or its row shows the other, with coordinates

- **Nov 18 2026: Changed in the lab (`app/proto/map-drawing/draw-map.tsx`, `drawing.ts`, `ui.tsx`, `app/proto/expand-and-draw/areas-panel.tsx`). Nothing in the product.** The designer, with a screenshot of the panel's hint line: "hover should show the point + coordinates." A row of the coordinates table and its point on the map were two separate things; now pointing at one shows the other.
  - **Both ways.** (1) Hovering or focusing a table row (or its magnifier, or a field in it) lights that point on the map (the dot grows to 1.5 times with a halo) and shows a tooltip over it with its number and coordinates, "2 -35.12345, 138.94321" (5 decimals, the same as the fields). (2) Hovering a point on the map highlights its row in the table (the `bg-brand-primary` fill) and shows the same tooltip. A circle's centre says "Centre lat, lon" and its radius handle "Radius X km"; the circle's latitude and longitude labels link to the centre and the radius label to the handle. The state is one value in the drawing controller (`hoverPoint`: the area and the point's index), so the table and the map read the same thing and the form's map and the expanded workspace behave alike.
  - **While a point is dragged,** the tooltip follows it and shows the live coordinates. After letting go the point stays lit while the pointer is still on it (it shows where it landed) and clears when the pointer leaves.
  - **Native title removed.** The markers' `title` (the browser's tooltip) is now an `aria-label` set on the element, so the screen shows one tooltip and not two, and the label still names the point to a screen reader.
  - **The hint line is shorter:** "Up and down nudge a number by about a metre (Shift: ten)." The sentence about the magnifier is gone, because the hover now says what it points at (the same fact is not said twice, 2.12, 4.3).
  - **Agent calls (each reversible in `draw-map.tsx` or `ui.tsx`).** The scale of 1.5 and the halo for the lit dot; the tooltip above the point; a tooltip is shown for a focus from the keyboard as for a hover; the row's highlight colour is the product's `bg-brand-primary`.
  - **Open, for the designer.** Whether hovering an area's card header should light all of its points. Whether the mid-edge "add a point" dots should show a tooltip (they do not now). Whether the tooltip should show the point's name rather than only its number once areas are nameable.
  - **Verified (18 Nov 2026, Chromium headless, 1440 by 900, real mouse):** zero console errors. At rest: no tooltip, no lit point. Hover on map point 2: tooltip "2 -35.12345, 138.94321", row 2 highlighted, one lit handle, native `title` null; leaving clears both. Hover on table row 2: the same handle lit, the same tooltip. Hover on the magnifier of point 1: "1 -35.12345, 138.54321". A field of row 3 focused: the tooltip for point 3. While dragging point 3: the tooltip updated live ("3 -35.34033, 138.90221"). After release the point stayed lit under the pointer. `npx tsc --noEmit` and `npx eslint app/proto` clean.
  - **Not checked.** A touch screen (there is no hover; a press on a point selects it and does not show the tooltip); a screen reader reading the `aria-label`; the tooltip near the map's edge (Leaflet flips it only in some cases); many points close together (the tooltips would overlap).
