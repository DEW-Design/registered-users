# 2026-11-17 - Names are optional, an occurrence defaults to its species, help icon on every field

- **Nov 17 2026: Names are optional, an occurrence defaults to its species, help icon on every field.** The designer: occurrence, observation and event names should be optional (an event's mandatory only if the selected methodology says so); "DEFAULT IT TO SPECIES NAME" for the occurrence; with no name, the event type and ID; and the help icon on all fields, everywhere it was added earlier.
  - **Names.** `autoName` (`record-rules.ts`) now names a record left blank by its species when it is an occurrence (its scientific name), and by its type and ID otherwise ("Transect SU00501", "Individual observation OB00012"). It replaces the type-and-sequence-number naming of 10 Nov 2026 ("Transect 3"). The card editor and the record form show that name as the field's placeholder, and the form no longer marks Name required (the Species row stays required, because the scientific name is). `missingFor` never required a name.
  - **Help icon.** `field-help.ts` gains an entry for every field a record draws that had none: ten described from the field's own name only (Site grouping, Specific property details, Mud map, Paddock, Photopoint disc number, Source ID, Event array, Species seq no., Institution rego #, Transfer date), the Opportune and Point intercept frame's own fields (Observers, Observation time, Record status, Comment type, Comment), Muir code, Canopy code, and each event type's own name and comment label. The record cards and the Manage concepts checklist both read the one map, so both gain it.
  - **An occurrence is named by its species: the name row is the species dropdown, narrowed by the taxonomic type (designer, same day, after two tries: a radio beside a species row, then a radio with the picker inside it, both "not intuitive").** No custom name: "there is no requirement to allow for the users to add a custom name". On an occurrence's card, Taxonomic type now comes before Occurrence name (`occurrenceSections`, so the view card too), and the Occurrence name row is the NSX code and species dropdown with no label of its own (`SpeciesControl`, `taxonomicType` narrows its list to that type's species). The separate "NSX code & species" row is not drawn in edit mode, so the species is asked once; its edit icon on the view card still scrolls to the picker. Changing the taxonomic type clears a chosen species of another type. The name is always the species: a save names the record by its scientific name (`fromDraft`), also over a name carried from before, so the tree shows the scientific name once a card is saved. The record drawer (`record-form.tsx`, not reached by a route, 3.14) no longer asks an occurrence for a name. `OccurrenceNameControl` was removed. Verified live on Superb Fairywren (OC00501): order Taxonomic type, Occurrence name; no radio; the list shows the 5 Fauna species; choosing Flora clears the species ("Choose a species") and lists the 2 Flora species. Not checked: saving, a new occurrence, Fungi (the list has no Fungi species, so its dropdown would be empty: a gap in the sample list), the other screens that say "Occurrence name" (map record detail, data model, ingestion), keyboard focus from the edit icon.
  - **Verified:** `tsc`, `eslint` on the five touched files, `check:contracts` OK. Live as BioData Admin on the Cleland Stringybark Woodland site: 23 help icons, every field row has one. Not checked: an occurrence or observation record, the name placeholders in the edit forms, touch, keyboard-only.

(4) Not given an icon: the table headings Code and Status and the trap effort and spec fields, which are not record fields. Not committed.
