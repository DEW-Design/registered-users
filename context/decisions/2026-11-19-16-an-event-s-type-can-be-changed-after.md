# 2026-11-19 - An event's type can be changed after it is saved, and its type is shown as a fact in the header

- **Nov 19 2026: An event's type can be changed after it is saved, and its type is shown as a fact in the header.**
  **The designer's brief.** "Need an option to change event type after its saved. Allow for the users to also know what event type they are working with."
  **Principles at stake (0.10).** Make it obvious (5): a person knows what kind of event they are in. One system (3): the same table that decides what may be added decides what a type may become. Say less (1) pulls against the first: the type is already in the eyebrow ("Event-Transect, TR00501"), so the header fact repeats it once, at body size, where Parent and the date are; it is for the designer to keep or drop (open below).
  **What changed.** (a) `record-rules.ts`: `eventTypeChoices` (the types an event may become: allowed under its parent, and able to hold every event already inside it, from `ALLOWED_CHILD_EVENTS`), `retypeEvent` (the new type's sections, each value carried by Darwin Core term and then by label, so "Transect name" becomes "Ramble name" and Observers follows its term to wherever the new type keeps it; trap effort, landscape scores and site scores go with their card when the new type has it; a Visit has no location; a Point intercept is one point) and `inheritersLosing`. (b) `edit-store.tsx`: `changeEventType(id, type)` checks the rule again, so no path can break it, saves the record (seed or added) and moves its notes and attachments to the renamed field keys (`fieldNotesActions.rekeyRecordNotes`). (c) `change-type-modal.tsx` (new): a `FormModal` with a `Select` of the allowed types, each with its description; if the new type has no field for something that was entered, a red `DestructiveModal` names what goes before anything is removed (CONTRACTS 3.12). (d) `record-quick-actions.tsx`: "Change type" in an event's "..." menu beside Duplicate, left out where no other type is allowed (2.12, 3.15). (e) `record-header-meta.tsx`: "Type" before Parent, for every event, in the full view, the side panel and a record being added. (f) CONTRACTS 3.12's icon table: "Change a record's type", `SwitchHorizontal02` (not `Edit05`, which is Edit, and two actions do not share an icon on one screen); rules regenerated.
  **Decided by the agent, to confirm.** The ID is kept when the type changes (TR00501 stays TR00501 as a Ramble), because notes, attachments and exports are found by it; one line (`nextCode`) re-issues it with the new prefix if the designer prefers. Only events change type; an occurrence or observation does not. The "..." menu is the home of the action, not the header fact.
  **Open.** (1) Keep the ID or re-issue it with the new type's prefix. (2) Keep the Type fact beside the eyebrow, or only the eyebrow. (3) The Opportune and Point intercept frames have "Observation time" where the other events have "Start time": they are not treated as the same field, so a Start time is listed as removed when an event becomes one of them; say if they are the same concept. (4) A Visit's "1/3" sequence number is worked out for the changed record only, as it is for a new one; the siblings' denominators are not recounted.
  **Verified.** `npx tsc --noEmit` clean; `npx eslint` clean on the six touched files and the new one; `npm run check:contracts` OK. In the browser (project BD-5039, BioData Admin, Playwright, scrollbars drawn): Transect to Ramble changes the header, the tree row ("Event-Ramble"), and the card and field names ("Ramble details", "Ramble ID", "Ramble name") with no confirm and 0 console errors; Transect to Opportune asks first and names "Start time"; Trap to Visit asks first and names Sample site dimensions, Location comment, Trap effort and Location; Keep as it is returns to the form with the choice kept; pressing Change type with no choice shows "Choose the type this event should be."; the choices for a Site, Visit, Block, Custom event and Quadrat match the sheet's table (a Site under the project is offered no Visit or Point intercept); a public user has no "..." menu; a record being added shows "Type Ramble". The new "Type" pair is Barlow 14px 400, the label rgb(112, 107, 104) and the value rgb(46, 41, 37), the same as Parent and the date beside it. Not verified: moving notes to a renamed field (the code path ran, no seeded note was on a renamed field), the toast that names records which now take their dates, observers or location from the event above (no seeded occurrence inherits), a role other than BioData Admin and Public user, touch emulation, the Prototype tools' other roles.
