# 2026-11-20 - The event nesting sheet becomes the rule for what can go where

- **Nov 20 2026: what an event may hold follows the business's "Allowed children events" sheet, which names Point intercept under every event.** The designer, with the sheet ("this is the data model - what can go under where") and the "Event - Point Intercept" concept mapping: "I think we need to add the point intercept event. looks like that might have gotten missed ... please sort this."
  - **Point intercept was not missing as an event.** It was built on 10 Nov from its own frame (`frameEventSections`, `Event:Point intercept` in `config/data-model-schema.ts`, the Add menus, the record page, the sample data). I compared the concept mapping with it field for field: name, ID (the record's own, structural), description, source ID, record status, observers, coordinates only, location method with its name, datum, reliability, location comment, start date, end date, date accuracy, duration, observation time, comment type and comment all match. What differed was the nesting: the 10 Nov rule was "any event can have any event" (except a Ramble in a Block, and a Site only under the project), and the sheet is stricter.
  - **The rule, in `record-rules.ts` (`CHILD_EVENTS`, `NEEDS_PARENT_EVENT`, `canContain`, `childOptions`; header comment lists the table).** Under the project: every event but a Visit or a Point intercept (the sheet's "must have a parent event"). Inside an event, only what its type lists: Site (Site, Visit, Ramble, Transect, Block, Trap, Custom event, Opportune, Point intercept); Visit (Site, Ramble, Transect, Trap, Custom event, Opportune, Point intercept); Ramble and Transect (Site, Visit, each other, Trap, Custom event, Opportune, Point intercept); Block (Site, Visit, Ramble, Transect, Trap, Custom event, Opportune, Point intercept); Trap (Site, Visit, Trap, Custom event, Opportune, Point intercept); Custom event (all); Opportune (Visit, Ramble, Transect, Block, Trap, Custom event, Opportune, Point intercept); Point intercept (Visit, Custom event). The sheet calls a Trap a "Trap Array" and a Custom event "Custom". Occurrences and observations are unchanged (under the project or any event).
  - **Changes from before.** A Site can sit inside an event (it could not). A Block can hold a Ramble (it could not, 10 Nov). A Visit can no longer go directly under the project, or inside a Visit or a Block. Self-nesting is only for Site, Trap, Custom event, Opportune and Point intercept. Every path that adds a record asks `canContain` (`edit-store.tsx addRecord`), so the Add menus and any other route agree.
  - **Quadrat.** The sheet has no Quadrat, the app and the Quadrat frame still do. It is kept, inside every event but a Point intercept or a Quadrat (the sample data has Quadrats in a Transect), holding what a Transect holds.
  - **Data model config.** `KNOWN_GAPS` in `config/data-model-schema.ts` has a new entry carrying the sheet and the open points (appended; the 10 Nov entry is kept as history). This edition has no `/config/data-model` page to show it on (the parent repo does), so it is not drawn anywhere here.
  - **Verified.** Every parent type's allowed children read out of `canContain` match the sheet; all event parent and child pairs in the project sample data and Explore's dataset satisfy it (0 violations, checked with jiti). Live (BioData Admin, Adelaide Hills): Add > Events directly under the project offers Site, Transect, Quadrat, Block, Ramble, Trap, Opportune, Custom event (no Visit, no Point intercept); on a Site it offers Site, Visit, Transect, Quadrat, Block, Ramble, Trap, Opportune, Point intercept, Custom event; zero console errors. `tsc`, `eslint` and `check:contracts` clean. Not checked live: the Add menu on a Visit, Opportune, Block or Point intercept (read from the function only), and moving existing records (there is no move path).
