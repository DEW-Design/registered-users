# 2026-11-17 - Home Quick actions are icon, label and arrow, and the first one is Manage projects and datasets

- **Nov 17 2026: Home Quick actions are icon, label and arrow, and the first one is Manage projects and datasets.** On the registered user's Home (`app/pages/_shared/home-dashboard.tsx`), the three Quick actions buttons now read leading icon, label, trailing arrow, and the first button's label changed from "Your projects and datasets" to "Manage projects and datasets". The designer's words: "Change this to manage projects and datasets", then "[Icon + label ->] format for quick actions".
  - **Override of 3.12, by the designer's instruction (0.1).** 3.12 allows a button an icon on the left *or* a forward arrow on the right, not both. These three carry both. The override covers these three buttons only; it is not a precedent for the next button (0.1).
  - **Icons chosen by the agent, not the designer.** Manage projects and datasets: `Folder`. Data licence request: `FileLock01`. Sensitive species nomination: `Feather`. They are the icons the cards for the same things already use on this screen (the project card, the DLA card, the nomination card), which keeps one thing to one icon (2.4). 3.12's table gives "request" and "add" `Plus`, and says two different actions must not share an icon on one screen; so Plus on both the DLA and nomination buttons was not used. Reverse by naming other icons; the three `iconLeading` props are the only lines.
  - **Names.** The label is not the Add menu's name for it ("Project", "Dataset"), which the 5 Oct audit entry (`2026-10-25-03`) had Quick actions follow. "Manage projects and datasets" opens the project list, which holds both.
  - **Open, for the designer.** (1) Whether these three icons stand, or the table in 3.12 should gain an entry for each ("Go to a list", "Request a licence", "Nominate"). The table is not edited here (9.4). (2) Whether the icon + arrow pair applies to every button that moves on, or only to Quick actions; as it stands it is only here.
  - **Also touched, not overridden by name above (2.4, 2.12, principle "Say less").** 2.4 says one icon per concept and no two icons side by side for one label; these are one on each side of the label, not side by side, and the pair is the designer's format. 2.12 says an icon in a button must carry meaning the text does not; the leading icons name the kind of thing (project, licence, species) and the arrow says it moves on. Whether that earns its place is the designer's call, and is part of the open question (2) above.
  - **Verified (17 Nov 2026, live page `/pages/dashboard/`, Chromium headless, scrollbars drawn):** at 320, 768 and 1440 wide, zero console errors; each of the three buttons has 2 icons (20px, the leading at x=12 inside the button and the arrow at the right end), 36px tall, Barlow 14px weight 600 (the Button's own text, so no new type layer, 2.9); no horizontal overflow (document scrollWidth equals clientWidth at all three; at 320 the widest button is 260px in a 272px row). `npx tsc --noEmit` clean, `npx eslint app/pages/_shared/home-dashboard.tsx` clean, `npm run check:contracts` OK (so `AUTO §3.12`, `3.12b` and `2.3` pass).
